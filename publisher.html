1. Why publishing exists

The live schedule at ashwinmatta.github.io/iiis-school-schedule is a static hosted HTML file.

  • When someone edits in the browser, changes often stay in that browser’s localStorage first.
  • Other staff still see the last published Netlify version until you redeploy.
  • So: Schedule Admin edits data → Publisher publishes when everyone must see it.
If nobody republishes, the school can think the site is “wrong” even though one admin’s browser looks updated.

2. When must you backup / update HTML / republish?

SituationBackup?Update HTML + republish?
Schedule Admin changed assignments, teachers, absences, holidays, HP windows and staff must all see it Yes Yes — required
New week cloned / template refreshed for school-wide use Yes Yes
Grok Build changed app features, password gate, help text, or preloaded datasets Yes Yes
Help guide content updated (this Help site) Optional but recommended Yes (help site deploy)
Someone only viewed the schedule / exported PDF No No
Schedule Admin is testing alone and does not want others to see yet Recommended before big experiments No until ready
Broken live site / bad deploy Use last good backup Yes — rollback republish

Simple rule

Republish whenever the “source of truth for everyone” must change. Viewing never needs a republish. School-wide data or app-file changes always do.

3. What to back up (and where)

Keep dated copies before every production deploy. The live app holds one school year only; see project file docs/YEAR-CYCLE.md for clone/backup cadence and how to start the next year without merging last year’s weeks.

  • IshaSchoolSchedule-YYYY-MM-DD.html — full app file (from Download full HTML or deploy folder)
  • schedule-YYYY-MM-DD.json — optional JSON export from the app File panel
  • Help site folder snapshot if Help content changed

Suggested folders:

  • Working deploy: ~/Downloads/iiis-schedule-deploy/index.html
  • Help deploy: ~/Downloads/iiis-schedule-help-deploy/
  • Project copy: …/School Schedule/IshaSchoolSchedule.html
  • Backups: create …/School Schedule/backups/ and store dated files there

4. End-to-end publish workflow (with Grok Build)

A. Get the latest schedule HTML from Schedule Admin

  1. Schedule Admin unlocks the live app and finishes edits.
  2. They click Download full HTML (and ideally Download JSON too).
  3. They send you those files (or save into a shared Drive folder).

B. Prepare the deploy file (critical)

  1. Backup the current live deploy file first.
  2. Replace ~/Downloads/iiis-schedule-deploy/index.html with the new HTML.
  3. Keep the filename exactly index.html.
  4. Confirm the staff lock screen / password gate is still present (search for siteGate or the staff password prompt). If the downloaded HTML lost the gate, ask Grok Build to re-inject it before publish.
Never deploy a file that removes the staff password gate unless leadership explicitly asks to go public again.

C. Ask Grok Build when needed

Use Grok Build for publisher tasks such as:

  • Re-applying the staff password gate after a raw HTML download
  • Preloading HP-approved windows / roster metadata into the HTML
  • Updating Help / Publisher guides
  • Fixing deploy scripts and running netlify deploy
  • Rolling back to a dated backup

Example prompts you can paste to Grok Build:

Backup current iiis-schedule-deploy/index.html to School Schedule/backups with today’s date.
Replace deploy index.html with the Schedule Admin’s downloaded HTML.
Re-inject the staff password gate (IIIS2026) if missing.
Redeploy Netlify site iiis-school-schedule to production.
Tell me the live URL and confirm the gate is present.

D. Redeploy to Netlify (production)

  1. Open Terminal.
  2. Run the production deploy for the schedule site:
cd ~/Downloads/iiis-schedule-deploy
../node_modules/.bin/netlify deploy --prod --dir=. --site 9ca2eaad-9d45-4f47-a870-dba701ef4ea9
  1. Wait for “Deploy is live!”
  2. Open a private/incognito window → https://ashwinmatta.github.io/iiis-school-schedule/
  3. Confirm: lock screen works, schedule data looks correct, Unlock still works for Schedule Admin.

E. Help site deploy (only when Help/Publisher docs change)

cd ~/Downloads/iiis-schedule-help-deploy
../node_modules/.bin/netlify deploy --prod --dir=. --site 0bbda351-233b-4762-a5ac-04c0422994e7

Help URL: https://ashwinmatta.github.io/iiis-school-schedule/help/

6. Cadence suggestions

  • Whenever Schedule Admin says “please publish” — same day
  • Before each major week rollout (e.g. new term week template) — backup + publish
  • After any Grok feature change — backup + publish + smoke test
  • Weekly — optional JSON/HTML backup even if no publish happened

7. Smoke-test checklist after every publish

  • Staff lock screen appears
  • Correct week data visible in Day-wise and Teachers views
  • Schedule Admin Unlock still works
  • Non-full-time HP blocking still works (spot-check one known teacher if relevant)
  • Help site still loads (if you also deployed help)
